# 开发路线与验收

本文件用于分配接手任务。状态只在相应验证完成后更新；“提供代码”“模拟通过”和“真实环境通过”分别记录。

**尚未接入真实抖音数据；Windows 实机和长时间高兵力压力测试未做。**

## 已确认的产品要求

- 正式目标环境为 Windows，同机运行游戏和采集器。
- 弹幕、点赞和礼物驱动互动；个人榜按贡献计分，较高积分主要来自礼物。
- 每位观众每局的非礼物基础贡献上限为 10000，礼物贡献另计。
- 画面为竖屏左右战场加全局小地图；主镜头随存活兵力分布平滑移动。
- 结束看板显示本局结果和贡献榜，倒计时 10 秒后自动重开；下一局清零。

当前已实现并通过本地模拟验证。初版参数为点赞 1 分、弹幕 20 分、每抖币礼物 10000 分，集中在 [`ContributionLedger.ts`](../src/game/live/ContributionLedger.ts)。礼物倍率及礼物到兵力的价值平衡仍可调整，不能把演示档位当作已验收的正式运营配置。

## P0 真实抖音事件接入

目标：保留已验收的模拟模式，同时增加 Windows 采集器到本地事件服务的真实适配。

主要入口为 [`live-interaction-runtime.mjs`](../scripts/live-interaction-runtime.mjs)、`LiveInteractionTester` 的连接与事件处理，以及[事件协议](EVENT_PROTOCOL.md)。先使用脱敏录制样本测试解析，再验证真实直播，避免用平台在线连接代替解析测试。

交付与验收：

- [ ] 目标房间的弹幕、点赞和礼物能驱动同一套出兵和贡献逻辑。
- [ ] 用户 ID 和消息 ID 无损保存；同名观众不合并，昵称变更不新建身份。
- [ ] 礼物按本次增量计分，连击累计量、结束包和重连重放不会重复计分或出兵。
- [ ] 区分目标房间、场次与本局编号；其他房间、身份缺失和异常消息有明确处理结果。
- [ ] 断开、重连、服务关闭及页面重开时，连接状态正确，不产生重复订阅。
- [ ] 明确结算期间的事件处理策略，保证上一局消息不串入下一局。
- [ ] 页面真实模式可操作，模拟模式及现有回归继续通过。
- [ ] 保存脱敏样本、解析测试和实际验证步骤；不提交 Cookie、密钥或原始观众隐私资料。

## P0 Windows 实机验收

目标：新机器从源码完成首次安装、资源准备、启动及完整对局。

- [ ] 在目标 Windows 机器验证 `start-live.bat` 和命令行启动，记录 OS、Bun、浏览器版本及硬件。
- [ ] 无预先提取缓存时，下载、WASM 提取、资源生成和构建成功。
- [ ] 已有缓存时可启动，并记录资源源站不可用时的本地包准备办法。
- [ ] 验证 Chrome 或 Edge 的 WebGL、窗口缩放、竖屏、拖动、滚轮与全局地图交互。
- [ ] 验证模拟对局、10 秒看板、新局积分重置和浏览器回归脚本。
- [ ] 验证端口冲突、启动失败提示、退出后重启；不结束其他软件的进程。
- [ ] 真实采集接入完成后，再验证采集器、游戏及直播采集画面的同机工作流程。

## P1 高兵力与长时间稳定性

当前浏览器回归会快速推进模拟 tick，因此不属于实时性能压测。先确定目标硬件、兵力规模、时长和通过门槛，再记录实际测试结果。

- [ ] 在真实定时循环中分档增加存活兵力和事件速率，记录帧率、模拟 tick 耗时、内存与 GPU 情况。
- [ ] 连续多局运行，检查内存是否持续增长、定时器或 SSE 是否重复、对象是否释放。
- [ ] 检查大批礼物/点赞事件下的队列、出兵位置、输入上限和页面响应。
- [ ] 覆盖大榜单、长昵称、异常数据、网络中断及窗口切换。
- [ ] 根据数据决定是否拆分重复素材条目、优化初始加载或限制/合并高频事件。
- [ ] 提交可重复的压测步骤及统计；未达到门槛时保留失败证据和问题清单。

## P1 正式玩法规则补齐

- [ ] 明确入场、阵营选择和换阵营规则，补齐进房等不计分事件与贡献记录之间的状态边界。
- [ ] 根据真实抖币价值确认礼物到兵力的档位；当前 500/2000 阈值保留自演示逻辑。
- [ ] 确认并测试贡献倍率、点赞/弹幕上限、同分排序、胜方无人贡献时的 MVP 展示。
- [ ] 如需跨局总榜或断线恢复，先明确保存范围和存储位置；当前只保证本局内存榜。

## 当前工程限制

| 限制 | 接手注意 |
| --- | --- |
| 浏览器独立模拟 | 多标签页不是同一个权威对局；新增多端观看需求时需先定义状态同步方案 |
| 历史不回放 | 本地事件服务只广播实时事件，重载页面无法恢复旧榜单 |
| 去重窗口有限 | 浏览器最多保留 5000 个事件 ID，真实接入需设计独立的重连去重策略 |
| 素材包含重复条目 | 当前可跑通，加载和内存成本仍需实测 |
| 资源来源字段简化 | 指定本地包时清单 URL 仍为默认源地址，后续可完善来源记录 |
| 部分上游命令缺脚本 | 以开发指南列出的现有入口为准，恢复旧命令时单独补齐测试 |

每个任务完成时更新相应勾选项、验证环境和证据链接。尚未完成的项目保持明确的待办状态。
